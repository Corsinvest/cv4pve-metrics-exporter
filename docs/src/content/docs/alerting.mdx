---
title: Alerting
description: Prometheus alert rules for Proxmox VE — exporter down, node down, quorum, storage almost full, guests without backup, replication, HA, SMART and subscription.
---

The Proxmox VE web interface shows problems when you look at it. With the exporter and Prometheus, the
problems come to you: a rule checks the metrics at every evaluation and fires an alert, which
Alertmanager sends by mail, chat or pager.

## Rules

Save them as `proxmox-alerts.yml` next to `prometheus.yml` and list the file under `rule_files`:

```yaml
rule_files:
  - proxmox-alerts.yml
```

```yaml
groups:
  - name: proxmox
    rules:
      # The exporter
      - alert: ProxmoxExporterDown
        expr: up{job="proxmox"} == 0
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Exporter {{ $labels.instance }} cannot read the cluster"

      - alert: ProxmoxExporterIncomplete
        expr: time() - cv4pve_scrape_last_success_timestamp_seconds > 900
        labels:
          severity: warning
        annotations:
          summary: "Some Proxmox VE calls fail on {{ $labels.instance }}"

      # Cluster and nodes
      - alert: ProxmoxClusterNotQuorate
        expr: cv4pve_cluster_quorate == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "Cluster {{ $labels.name }} has lost quorum"

      - alert: ProxmoxNodeDown
        expr: cv4pve_up{type="node"} == 0
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Node {{ $labels.id }} is offline"

      - alert: ProxmoxSubscriptionExpiring
        expr: (cv4pve_node_subscription_next_due_timestamp_seconds - time()) / 86400 < 30
        labels:
          severity: warning
        annotations:
          summary: "Subscription of {{ $labels.node }} expires in {{ $value | humanize }} days"

      # Guests
      - alert: ProxmoxGuestDown
        expr: (cv4pve_up{type=~"qemu|lxc"} == 0) * on (id) group_left (name, node) cv4pve_guest_info{tags=~"(.*;)?monitor(;.*)?"}
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Guest {{ $labels.name }} ({{ $labels.id }}) is not running"

      - alert: ProxmoxGuestLocked
        expr: cv4pve_guest_lock{state!="suspended"} == 1
        for: 12h
        labels:
          severity: warning
        annotations:
          summary: "Guest {{ $labels.id }} is locked ({{ $labels.state }}) for more than 12 hours"

      # Storage
      - alert: ProxmoxStorageAlmostFull
        expr: (cv4pve_storage_usage_bytes / cv4pve_storage_size_bytes > 0.9) * on (id) group_left (node, storage) cv4pve_storage_info
        for: 15m
        labels:
          severity: warning
        annotations:
          summary: "Storage {{ $labels.storage }} on {{ $labels.node }} is {{ $value | humanizePercentage }} full"

      # Data protection
      - alert: ProxmoxGuestNotBackedUp
        expr: cv4pve_not_backed_up_info * on (id) group_left (name, node) cv4pve_guest_info{template="0"}
        for: 1h
        labels:
          severity: warning
        annotations:
          summary: "No backup job includes {{ $labels.name }} ({{ $labels.id }})"

      - alert: ProxmoxReplicationFailing
        expr: cv4pve_replication_fail_count > 0
        for: 15m
        labels:
          severity: warning
        annotations:
          summary: "Replication job {{ $labels.id }} to {{ $labels.target }} fails ({{ $value }} attempts)"

      - alert: ProxmoxReplicationStale
        expr: time() - cv4pve_replication_last_sync_timestamp_seconds > 7200
        labels:
          severity: critical
        annotations:
          summary: "Replica of guest {{ $labels.guest }} on {{ $labels.target }} is older than 2 hours"

      # HA
      - alert: ProxmoxHaNotQuorate
        expr: cv4pve_ha_quorate == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "The HA manager has no quorum"

      - alert: ProxmoxHaResourceProblem
        expr: cv4pve_ha_state{state=~"error|fence|recovery"} == 1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "HA resource {{ $labels.sid }} is in state {{ $labels.state }}"

      - alert: ProxmoxHaNodeNotOnline
        expr: cv4pve_ha_node_state{state=~"unknown|fence|gone"} == 1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "HA node {{ $labels.node }} is {{ $labels.state }}"

      # Disks
      - alert: ProxmoxDiskSmartFailed
        expr: cv4pve_node_disk_health == 0
        labels:
          severity: critical
        annotations:
          summary: "SMART health of {{ $labels.dev_path }} ({{ $labels.serial }}) on {{ $labels.node }} is not good"

      - alert: ProxmoxDiskWornOut
        expr: cv4pve_node_disk_wearout < 10
        labels:
          severity: warning
        annotations:
          summary: "SSD {{ $labels.dev_path }} on {{ $labels.node }} has {{ $value }}% of its life left"
```

Check the file with `promtool check rules proxmox-alerts.yml` before reloading Prometheus. The
thresholds — 90% storage, 2 hours of replication, 30 days of subscription, 10% of SSD life — are starting
points: change them to fit your cluster.

## What each rule needs

| Rule | Collector that must be on | Notes |
|---|---|---|
| `ProxmoxExporterDown` | — | `up` is set by Prometheus: `0` when the exporter does not answer, or answers 503 because it cannot connect or log in to Proxmox VE. Change `job` if yours has another name |
| `ProxmoxExporterIncomplete` | — | Some calls fail on every scrape — a node down, a missing privilege. The other rules may then see old values |
| `ProxmoxClusterNotQuorate`, `ProxmoxNodeDown` | — | |
| `ProxmoxSubscriptionExpiring` | `Node.Subscription` | Only nodes with a due date |
| `ProxmoxGuestDown` | — | Only guests with the tag `monitor` — see below |
| `ProxmoxGuestLocked` | — | A lock left behind by an interrupted backup, snapshot or migration. `suspended` is left out: a hibernated VM keeps it on purpose |
| `ProxmoxStorageAlmostFull` | — | A shared storage fires once per node |
| `ProxmoxGuestNotBackedUp` | `Cluster.BackupInfo` | Templates are left out |
| `ProxmoxReplicationFailing`, `ProxmoxReplicationStale` | `Node.Replication` | |
| `ProxmoxHaNotQuorate`, `ProxmoxHaResourceProblem`, `ProxmoxHaNodeNotOnline` | `Cluster.Ha` | |
| `ProxmoxDiskSmartFailed`, `ProxmoxDiskWornOut` | `Node.DiskSmart` | Off in the standard profile: use `--full` or turn it on in the settings |

## Which guests should be running

`cv4pve_up` is `0` for every stopped guest, including those stopped on purpose — test VMs, templates,
cold spares. Alerting on all of them would be noise. Two ways to choose:

- **HA resources** are watched by `ProxmoxHaResourceProblem`: the HA manager already knows they must run.
- **Other guests**: give them a tag in Proxmox VE — the rule above uses `monitor` — and the alert covers
  only them. Tags are in the `tags` label of `cv4pve_guest_info`; add or remove the tag in the web
  interface, no change to the rules is needed.

## Backup jobs that fail

The exporter tells whether a guest is included in a backup job (`ProxmoxGuestNotBackedUp`), not whether
the backup succeeded: it does not read task logs. For failed backups use the notifications of the backup
jobs in Proxmox VE.
