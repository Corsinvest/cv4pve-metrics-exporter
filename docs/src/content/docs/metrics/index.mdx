Every metric starts with `cv4pve_`. The pages of this section list each one with its type, labels,
unit and meaning, grouped by what it describes. This page explains the conventions they share and
indexes them all.

## Conventions

### The `id` label

Guests, storages and nodes are identified by the `id` label, which is the resource ID used by Proxmox VE
itself:

| Resource | `id` |
|---|---|
| Node | `node/pve01` |
| VM | `qemu/100` |
| Container | `lxc/101` |
| Storage | `storage/pve01/local-zfs`, one per node, also for a shared storage |
| Cluster (only in `cv4pve_up`) | `cluster/pve-cluster` |

Per-node metrics use a `node` label with the node name instead.

### Info metrics

Names, tags, versions and other text are not repeated on every series: they are labels of an
`…_info` metric whose value is always `1`: `cv4pve_guest_info`, `cv4pve_node_info`,
`cv4pve_storage_info`, `cv4pve_node_version_info`, `cv4pve_node_subscription_info`, `cv4pve_cluster_info`.
Join them in a query to add the label you need:

```txt
# Memory used by each guest, with its name and node
cv4pve_guest_memory_usage_bytes
  * on (id) group_left (name, node) cv4pve_guest_info
```

### State metrics

A state with a fixed set of values (a guest lock, an HA state, a subscription status) is exported as
one series per possible value, with a `state` (or `status`) label, and value `1` for the current state
and `0` for the others. The alert is then a plain comparison, and a guest that stays locked keeps the
same series:

```txt
cv4pve_guest_lock{state="backup"} == 1
```

### Units and types

- Sizes are in **bytes**, durations in **seconds**, points in time are **Unix timestamps** in seconds.
- `…_ratio` metrics go from `0` to `1`.
- Metrics ending in `_total` are **counters**: use them with `rate()` or `increase()`. A counter goes
  back to zero when Proxmox VE resets it (a guest restarted or migrated) or when the exporter restarts;
  Prometheus handles both.
- Everything else is a **gauge**, except `cv4pve_api_request_duration_seconds`, a **histogram**.

### Always on, or turned on by a setting

The metrics built from the two cluster-wide calls, `/cluster/status` and `/cluster/resources`, are
always exported. The others come from a collector, turned on and cached by a
[setting](/cv4pve-metrics-exporter/settings/). A collector that is off exports no series at all.
